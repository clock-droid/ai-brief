구글 딥마인드(Google DeepMind)에서 개발자 관계를 맡고 있는 필립 슈미트(Philipp Schmid)가 11월 26일 자기 블로그에 '왜 나는 2027년 MCP에 낙관적인가(Why I'm Bullish on MCP for 2027)'를 올리고 X에도 요지를 남겼어요. 결론은 X 글 마지막 문장 그대로예요. 가장 좋은 에이전트 하네스(모델에 도구·실행 환경을 붙여 일을 시키는 프로그램)는 가장 좋은 MCP 클라이언트를 가진 쪽이 될 거라는 것. 아래는 글 흐름 순서의 요약이고, 전망은 모두 슈미트의 판단이에요.

**MCP가 뭐였고, 왜 미움받았나**

MCP(Model Context Protocol)는 AI 모델이 외부 도구·데이터에 붙는 방식을 하나로 맞춘 공개 규격이에요. 앤트로픽이 2024년 11월 내놨는데요. 기기마다 다르던 충전 단자를 USB-C 하나로 맞춘 것처럼, 서비스마다 따로 만들던 연결을 한 규격으로 처리하자는 생각이에요.

슈미트는 MCP가 지난 18개월 동안 과대광고 주기를 한 바퀴 다 돌았다고 봤어요. 처음엔 열광했지만 곧 반발이 왔고, 가장 큰 불만은 '맥락 비대(context bloat)'였어요. 연결한 서버의 도구 설명이 전부 프롬프트에 들어가 모델이 읽을 자리를 잡아먹는다는 것. 그러다 앤트로픽의 '스킬(Skills)'이 나오자 개발자 다수는 필요할 때만 설명서를 펼쳐 보게 하는 방식(점진적 공개)과 명령줄 도구(CLI) 쪽으로 옮겨 갔어요. 슈미트는 그 흐름을 믿지 않았고, 이제 분위기가 바뀌고 있다고 했어요.

근거로 든 숫자가 있어요. 리니어(Linear)와 노션(Notion)에선 에이전트가 이슈·페이지의 약 절반(주당 약 240만 건)을 만들고, 노션은 MCP 트래픽이 60배 늘었다고 해요. 아틀라시안(Atlassian)에선 MCP가 평일 하루 500만 건 넘는 도구 호출을 처리하는데, 그 사용자의 44%는 CLI를 쓸 일이 없던 비개발 부서 사람이라고. 네온(Neon)의 MCP 경유 에이전트 사용은 매주 14%씩 늘고, 애플도 페이지스·넘버스·키노트용 로컬 MCP 서버를 낸다고 했어요. 규격 자체도 2026년 7월 28일 판에서 상태를 유지하는 세션을 없애고 공식 확장을 들였다고 해요.

**1. 코드 모드와 타입 있는 출력**

실제 일은 도구 호출 한 번으로 끝나지 않아요. 열린 이슈를 나열하고, 세부를 읽고, 오류를 확인하고, 요약을 쓰는 식이에요. 예전 방식에선 단계마다 모델이 한 턴씩 돌고 중간 결과가 전부 맥락에 쌓였어요. 서버 두 개의 데이터를 합치려면 모델의 맥락을 임시 메모리처럼 써야 했던 것.

'코드 모드(Code Mode)'는 도구 50개의 설명을 프롬프트에 넣는 대신, 모델에게 격리된 실행 공간(샌드박스)을 주고 MCP 도구를 함수처럼 부르게 해요. 모델은 스크립트 하나로 여러 호출을 엮고, 걸러내고 합치는 일은 메모리 안에서 처리한 뒤 필요한 결과만 돌려받아요. 슈미트는 이 방식이 오픈코드(OpenCode) 2.0, Claude Code, OpenAI 코덱스(Codex), 파이(Pi), 팩토리 드로이드(Factory Droid)에서 이미 기본이 되어 가고 있다고 했어요. 이게 잘 되려면 모델이 도구가 무엇을 돌려줄지 미리 알아야 해서, 서버가 입력 형식과 함께 출력 형식(outputSchema)도 밝히는 게 중요하다고 했어요.

CLI와 비교한 장점도 들었어요. MCP는 도구 결과에 이미지·소리를 함께 담을 수 있고, 인증도 깔끔하다는 것. CLI는 API 키를 디스크나 환경변수에 넓은 권한으로 둬야 하지만, MCP 클라이언트는 사용자별 OAuth 2.1 로그인과 도구별 권한을 샌드박스 바깥에서 처리해 에이전트에게 날것의 비밀번호를 넘기지 않아도 된다고 해요.

**2. 스킬이 MCP 안으로**

지금까진 CLI나 MCP 서버를 만들고, 에이전트에게 사용법을 가르치는 SKILL.md 파일을 따로 관리해야 했어요. 새 스킬 확장은 스킬을 MCP 서버가 직접 내려주게 해요. 스킬마다 파일 목록과 SHA-256 지문(파일 내용이 바뀌면 함께 바뀌는 값)이 붙어서, 회사가 스킬을 고치면 클라이언트가 알아서 새 판을 받아 가요. 팀 전체가 스킬을 최신으로 맞추는 골칫거리가 풀린다는 것. 슈미트는 앤트로픽이 Claude와 Claude Code에서 MCP 경유 스킬을 공개 베타로 냈고, 쇼피파이·허브스팟·아틀라시안 같은 서버가 로그인한 사용자 조직에 맞춘 사용법을 내려줄 수 있게 됐다고 전했어요. 맥락 부담은 가볍게 유지돼요. 처음엔 스킬 이름과 한 줄 설명만 넣고, 필요할 때 본문을 읽는 방식이에요.

**3. 늘 켜져 있는 에이전트, MCP 이벤트**

지금까지 MCP 연결은 에이전트가 먼저 물어봐야만 답하는 구조였어요. 바깥에서 무슨 일이 생겨도 에이전트를 깨울 수 없었던 것. 베타로 나온 이벤트 확장은 세 가지 전달 방식을 둬요. 사용자가 자리를 비운 사이 서버가 서명된 요청을 보내는 웹훅, 빌드 로그처럼 연결을 열어 두고 흘려보내는 스트림, 공개 주소가 없는 데스크톱 앱용 주기적 확인(폴링)이에요. 슈미트가 든 예는 새벽 2시의 최고 등급 보안 경보예요. 경보가 뜨면 에이전트가 깨어나 로그를 모으고, 누가 받은편지함을 열기 전에 1차 분석을 올려 둔다는 것. 쇼피파이의 주문 업데이트, 버셀(Vercel)의 배포 성공 알림이 이미 이벤트를 지원한다고 해요.

**4. MCP 앱, 채팅 안의 화면**

지연 시간 그래프를 들여다보거나 대시보드를 거르려면 JSON과 글자만으론 부족해요. MCP 앱은 서버가 격리된 HTML 화면을 돌려줘 채팅 안에서 바로 띄우게 해요. 슈미트는 슬랙의 새 MCP 클라이언트, Claude의 대화형 커넥터, 구글 안티그래비티(Antigravity)가 이미 이 방식을 지원한다고 했어요.

**아직 남은 문제**

슈미트는 빈틈도 셋 꼽았어요. 첫째, MCP 서버는 도구 호출만 보고 사용자의 대화는 못 봐서 왜 불렸는지 모른다는 것. 둘째, 서버를 등록소 다섯 곳에 따로 올리는 식으론 확장이 안 돼서, 웹사이트 정해진 주소(/.well-known)에 서버 정보를 두고 자동 보안 검사를 붙이는 식의 발견 방법이 필요하다는 것. 셋째, 바깥에서 들어오는 웹훅 내용, 코드 모드 샌드박스, 채팅 안에 띄우는 화면이 모두 프롬프트 주입(외부 내용에 숨긴 지시로 에이전트를 조종하는 공격)의 통로를 넓힌다는 것이에요.

**하네스도 MCP 서버가 돼야 한다**

마지막으로 그는 하네스가 별도의 다중 에이전트 규약을 만들지 말고 스스로 MCP 서버가 되라고 제안했어요. 하위 에이전트는 MCP 작업(Tasks)으로 돌리고, 공유 게시판 도구로 발견을 올리고 일을 나눠 맡고, 이벤트로 서로를 깨우는 식이에요. 동시에 SaaS 제품 전체를 질문 창구 하나(ask_agent)로 감싸는 건 반대했어요. 그러면 내 에이전트가 이미 가진 맥락을 못 쓰게 된다는 것. 그의 문장으로는 "좋은 MCP 서버는 에이전트를 위한 도구를 내놓지, 에이전트를 도구로 내놓지 않는다(Good MCP servers expose tools for agents, not agents as tools)".

다만 글에 나온 기업별 사용량은 슈미트가 각 회사 발표를 모은 것이고, 측정 방식이 서로 같은지는 글에 나오지 않아요. 이 글은 구글 소속 개발자의 개인 전망이에요.
