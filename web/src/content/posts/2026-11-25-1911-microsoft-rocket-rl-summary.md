마이크로소프트 AI(MAI)가 11월 23일 공개한 15쪽짜리 기술 보고서 "마이크로소프트 AI의 강화학습 인프라(RL infrastructure at Microsoft AI)"를 원문 흐름대로 요약했어요. 보고서는 MAI가 직접 만든 강화학습 틀 '로켓(Rocket)'이 어떤 문제를 어떻게 풀었는지 설명해요.

**출발점: 증류 없이 기반 모델에서부터**

MAI는 지난번 공개한 3조 파라미터 기반 모델 'MAI 베이스 2(MAI Base 2)'를 지금 로켓으로 후속 학습하고 있고, 다른 연구소 모델에서 증류하지 않는다고 밝혔어요. 증류(distillation)는 더 강한 '선생' 모델의 답을 따라 배우게 하는 방법인데요. 보고서는 이렇게 시작한 모델은 강화학습을 천장 가까이에서 시작하므로 강화학습이 짧은 다듬기 단계가 되고, 실패하면 다시 돌리면 그만이라고 봤어요. MAI처럼 기반 모델에서 강화학습만으로 오르려면 몇 주~몇 달, GPU 수천 개 규모로 돌려야 하고, 그러면 하드웨어 고장은 "확실히" 일어나며 작은 수치 오차가 수천 번의 갱신 동안 쌓인다는 것.

보고서는 verl·slime 같은 공개 강화학습 틀이 좋은 토대지만 이렇게 긴 학습은 그 틀들이 흔히 쓰이는 범위를 넘는다고 보고, 학습 틀(로켓)과 SGLang을 고친 자체 추론 엔진을 함께 직접 운영한다고 설명했어요.

**문제 1: 낡음 — 답을 만든 모델과 배우는 모델이 달라진다**

로켓은 그룹 상대 정책 최적화(GRPO)를 써요. 같은 문제를 여러 번 풀게 한 뒤 답끼리 점수를 비교해 더 나은 쪽을 배우는 방식이에요. 문제는 작업 길이가 제각각이라는 점인데요. 하루치 실제 학습 113만 건을 보면 지시 따르기는 중앙값 2분, 웹 조사는 51분(모델 호출 89번), 소프트웨어 개발은 93분(249번)이 걸렸어요. 그 사이 학습은 계속되니, 답을 만들 때 쓴 모델 버전과 그 답으로 배울 때의 모델 버전이 벌어져요. 보고서는 이 차이를 '낡음(staleness)'이라 부르고, 낡을수록 두 모델이 매기는 단어 확률 차이가 커지는 그래프를 보여 줬어요.

예시로 든 한 그룹에서는 가장 빨리 끝난 답이 가장 느린 답을 7.6시간이나 기다렸어요. 로켓의 대응은 네 가지예요. 가중치를 15초 만에 추론 서버들로 보내 자주 갱신하고, 이미 시작한 작업을 새 작업보다 먼저 처리하고, 실패한 작업은 다시 돌리지 않고 버리고, 학습 GPU를 일부러 넉넉히 둬 완성된 답이 줄 서서 기다리지 않게 했어요(예시 그룹은 12초 만에 학습에 들어감). 다만 실패한 작업을 버리면 GRPO의 비교 기준이 치우칠 수 있다고 보고서도 인정했어요. 추론 서버를 늘리면 학습 단계가 빨라져 오히려 낡음이 커질 수 있다는 반직관적인 점도 짚었어요.

**문제 2: 계산의 어긋남 — 같은 모델인데 숫자가 다르다**

모델이 커지자 MAI는 추론 쪽 메모리를 아끼려고 전체 파라미터의 95% 이상인 전문가(MoE) 가중치와 일부 KV 캐시를 MXFP8이라는 8비트 형식으로 저장했어요. 이전 모델 MAI 싱킹 1 때는 16비트(BF16)를 그대로 썼는데요. 대신 계산할 때는 16비트로 되돌리고, 학습 쪽에서도 같은 압축·복원을 흉내 내서 양쪽 결과를 맞췄다고 해요. 이렇게 해서 전역 문맥을 약 67% 더 담을 수 있게 됐다고.

더 나아가 같은 입력이면 추론 쪽과 학습 쪽 계산 결과가 비트 하나까지 같도록 맞췄다고 밝혔어요. GPU 여러 대에 나눠 더할 때 순서가 달라지면 끝자리가 달라지는 문제를, 덧셈을 한 GPU에서 같은 순서로 하게 하는 식으로 풀었다는 것. 흥미로운 관찰은 학습이 진행될수록 이 차이가 처음보다 커졌다는 점이에요. 보고서는 "최적화가 수치 차이를 키우거나 악용할 수 있다"고 봤어요. 활성 70억·전체 1,800억 파라미터 모델로 한 비교에서 비트 일치를 적용한 쪽이 같은 단계에서 수학 점수가 더 높았다고 해요.

**문제 3: 고장과 재배치 — 전체를 다시 켜지 않기**

몇 주짜리 학습에서는 고장이 잦아요. 로켓은 학습 부분만 죽으면 추론 서버는 계속 돌리면서 약 5분 만에 학습 부분만 되살리고, 추론 서버 하나가 죽으면 그것만 바꿔요. 학습 중에 GPU 배치나 데이터 비율을 바꾸는 것도 멈추지 않고 할 수 있어요. GPU 6,000개를 가정한 추산에서 학습 부분 복구로 7.07%, 실행 중 설정 변경으로 9.88%, 합쳐서 전체 GPU 시간의 17.37%(약 260만 GPU시간)를 아꼈다고 했어요.

**결과와 남은 질문**

보고서 마지막 그림은 수십 개 공개·비공개 평가를 합친 MAI 자체 종합 벤치마크에서 점수가 학습 단계에 따라 꾸준히 오르는 모습이에요. MAI는 다음 모델이 최근 클로드 오퍼스 4.8(66.0%)을 넘었고 "몇 주 안에" GPT-5.6 솔(73.3%)도 넘을 것이라고 밝혔어요. 보고서의 표현으로는 "정체하거나 불안정해지지 않고" 올랐다는 것.

다만 비교 대상은 두 회사의 이전 세대 모델이고, 벤치마크 구성과 모델은 공개되지 않아 외부에서 확인할 수 없어요. 앞으로 더 큰 차세대 모델과 복잡한 에이전트 작업으로 규모를 키우겠다는 게 MAI의 계획이에요.
